# E5 — Live Tracker Reality Check

**Status: PASS (with two engineering conditions) — closed 2026-07-30 on
the seated body clip. Pose-lite is stable enough to drive the E6 proxy
*provided* (1) end effectors get a One Euro filter (wrist jitter σ ≈ 32 px
@1080p raw) and (2) the tracking layer adds detection hysteresis
(edge-of-frame produces flickery single-frame detections). Torso/head are
solid raw. See "Stability results".**

Run 2026-07-29. Spike: `spikes/e5-tracker-probe/` (venv + MediaPipe
1.0.0, `pose_landmarker_lite` float16, CPU/XNNPACK).

## Cost (valid regardless of scene content)

| Metric | Value |
| --- | --- |
| inference ms p50 / p95 / max | **12.9 / 21.4 / 24.1** |
| implied standalone rate | ~77 Hz |
| criterion (≥15 Hz under contention) | large margin available |

Caveat recorded honestly: the clip has no person, so the detector may be
early-exiting; with a body in frame the landmark refinement path runs and
per-frame cost can rise. The margin (5× over the bar) makes the verdict
robust to that, but the with-person number should still be captured when
the stability pass runs.

## Stability results (closed 2026-07-30, seated body clip)

Clip: `out-clip-body`, 887 frames @30 Hz — pose hold, fast seated swings,
full out-of-frame excursion, close portrait lean. Seated means hips-down
were out of frame for most of the clip, which doubles as the truncation
test. Analysis script: `spikes/e5-tracker-probe/e5_stability.py` (method:
motion energy segments the clip; jitter σ detrended with a 15-frame
moving average so slow sway doesn't count).

| Criterion | Measured | Verdict |
| --- | --- | --- |
| Detection rate overall | 92.8 % (absences = the out-of-frame segment) | ✅ |
| Dropout during fast swings (222 top-quartile-motion frames) | **0.00 %** | ✅ |
| Held-pose jitter σ @1080p | nose 4.5 px, shoulders 6–8 px, elbows 19–22 px, **wrists 32–33 px** | ⚠ torso/head fine; end effectors need One Euro |
| Reacquisition after full absence | ≤ a few frames once visibly back (longest true gap 16 fr = 0.53 s spanning the actual exit) | ✅ |
| Edge-of-frame behavior | flickery 1–5-frame detection dropouts while half-visible (frames 532–667) | ⚠ needs hysteresis in the tracking layer |
| Portrait truncation (hips invisible) | 78.5 % of detected frames; shoulders at 1.0 visibility throughout | ✅ graceful |

Contention case (tracker + kstudio live simultaneously) remains unmeasured
but is bounded by E4's ~30 % CPU headroom + this tracker's 12.9 ms on a
different thread; fold it into the E6 harness run rather than a separate
session.

## Interim consequence

MediaPipe pose (lite) as the phase-7 live provider candidate looks
comfortably affordable next to E4's render budget (it runs on CPU; the
render thread never sees it). RTMW3D evaluation stays deferred to the
recorded-take lane as planned. Weights/dataset license clearance still
gates phase-7 adoption (discovery 10).
