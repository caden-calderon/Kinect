## Priority 1 — Background-plate subtraction (user isolation)

Caden explicitly wants the instrument focused on the performer.
`clip_far` cropping works but amputates hands near the sensor and kills
him when he leans back. Depth-plate subtraction fixes it at any range.

Spec:
- **Capture:** a "capture background" button in kstudio (and a
  `--capture-plate` path if trivial). User steps out; accumulate N = 60
  depth frames; per-pixel plate = median of valid samples; pixels with
  < 20 % valid samples are marked "unknown" (never subtract on unknown).
  Store as a 512×424 u16 (0.1 mm) raster.
- **Apply:** in `src/render/shaders/observed_geometry.comp` (which
  already reads the depth texture and has the clip/crop uniforms): if
  plate is enabled and `|depth − plate| < epsilon_mm` → treat the pixel
  as invalid (same path as depth 0). `epsilon_mm` is a parameter,
  default 60, range 20–200. A `background_removal` on/off param gates it.
- **Persistence:** save/load the plate as a file next to presets
  (`presets/<name>.plate`, raw u16 + a small header with dims and
  capture date). A plate is scene-specific; loading a preset must NOT
  implicitly load a plate.
- **Plumbing:** plate lives in `ObservedPipeline` as one extra R16UI
  texture; capture accumulates on CPU from `RgbdFrame::depth` (the
  renderer already sees every frame via the LatestSlot) — no capture-side
  changes needed. Keep allocation at init/capture time only, nothing
  steady-state.
- **Tests:** plate math (median, valid-fraction, epsilon compare) is pure
  CPU logic — unit-test it (`tests/`), no hardware needed.

## Phase 4 (motion field) — CORE BUILT 2026-07-30 (this session)

The live flow engine exists and is verified end-to-end:

- `src/motion/flow_engine.{hpp,cpp}` — DIS on a worker thread, fed from
  the assembler sink (live and replay identically). Computes per distinct
  color frame: forward+backward DIS, per-pixel FB confidence, packs
  [fx, fy, conf, |v|] into a 512×424 RGBA32F texture. Pool of 3 field
  buffers, latest-wins handoff, all skips/drops counted
  (`flow.*` telemetry).
- Sampled per depth pixel through the existing registered-color UV
  (binding 5 in `points.vert`); **color mode "flow"** visualizes it live
  (hue = direction, brightness = confidence-gated magnitude). Params:
  `motion.enabled/preset/flow_gain/flow_conf_min`.
- Two hard-won determinism facts, now load-bearing (comments in
  flow_engine.cpp): OpenCV DIS is **not bit-deterministic under its
  internal threading** → pinned to 1 thread (also faster at this size,
  2.9 vs 3.4 ms p50); DIS treats any non-empty flow argument as a warm
  init with non-reproducible results → the output Mats are released each
  call so every field is a pure function of its frame pair (seekable
  replay). 4 unit tests cover translation recovery, bit-determinism,
  BGRX→gray correctness, and thread plumbing.
- Verified: static real take shows zero false motion (floor color);
  golden take shows its genuinely uniform scroll; 31/31 tests green.

**What remains of phase 4** (fusion + look, still capable-model work):
